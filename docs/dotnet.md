# Переход на .NET

Вся игра — движок, сервер, клиент и наша логика — переезжает на C#. Desktop: Silk.NET (WebGPU, OpenAL Soft,
Windowing, Input). Web: Blazor WebAssembly и WebGPU. Моды — на C#, собранные в wasm, через систему плагинов
UserPluginSystem. Здесь — карта нынешнего кода, принятые решения, устройство решения на .NET, порядок работ и риски.

Этот документ заменяет направление Rust и Luau: `docs/engine.md` (§3–§9), `docs/content.md` (§4а, §6, К4–К7),
`docs/client.md`. Из них по-прежнему верно, **что** делает игра и где граница движка и контента. **На чём** это
написано, решает этот документ.

## 1. Решения

Решения приняты в разговоре 2026-10-18.

| # | Вопрос | Решение |
|---|---|---|
| Р1 | Что переносим | **[решено, 2026-10-18]** Всё на C#. Luau уходит совсем, вместе с ним `mods/base` на Luau и `crates/content`. |
| Р2 | Где исполняются моды | **[решено, 2026-10-18]** На хосте и на клиенте. Хост — правила. Клиент — подача, мир доступен только на чтение, менять его можно только приказом. Код клиентских модов приходит с сервера. Браузерный бэкенд плагинов нужен с первого дня. |
| Р3 | Где живёт состояние мода | **[решено, 2026-10-18]** В мире. Мод объявляет компоненты и `storage`, движок держит их столбцами, сохраняет и шлёт по сети. Система мода — чистая функция: столбцы на вход, команды на выход. Экземпляр wasm можно выбросить в любой момент, пул в системе плагинов остаётся. |
| Р4 | Наша логика | **[решено, 2026-10-18]** `base` — такой же wasm-мод, как чужие. Привилегий у него нет: всё, что может base, может и мод. Движок даёт только инструменты (§4.1). |
| Р5 | Сборка мода | **[решено, 2026-10-18]** NativeAOT-LLVM, ядровой модуль wasm (не компонент). Экспорты через `UnmanagedCallersOnly`, импорты WASI заглушает хост. Один и тот же `.wasm` работает в Wasmtime и в браузерном `WebAssembly`. |
| Р6 | Переезд | **[решено, 2026-10-18]** Рядом, затем вайп. TS-игра живёт и выкладывается как есть, служит эталоном поведения: тесты, `tools/harness`, `bun run balance`. .NET строится в `dotnet/` со своим протоколом и сохранением. При паритете — переключение, старые сохранения не переносятся. После — TS, Rust и Luau удаляются. |
| Р7 | Платформы | **[решено, 2026-10-18]** Windows, Linux, macOS (Silk.NET, NativeAOT); браузер (Blazor WASM, AOT); сервер на Linux x64 и arm64. Телефоны — через браузер с сенсорным вводом. Нативные iOS и Android — вне плана, но архитектура их не закрывает. |
| Р8 | Запасной WebGL 2 | **[решено, 2026-10-18]** Нет, только WebGPU. Один рендер, один набор шейдеров WGSL. Без WebGPU игра говорит, какой браузер нужен. До переключения есть время посмотреть по TS-версии, сколько игроков без WebGPU. |
| Р9 | Звук | **[решено, 2026-10-18]** Один API графа в терминах Web Audio, две реализации. Desktop — свой DSP на C# в аудиопотоке, вывод потоковыми буферами в OpenAL Soft. Браузер — тот же граф из настоящих узлов `AudioContext`, собирается пачкой через interop. Сэмплы синтезирует C# одинаково везде. |
| Р10 | Хост в браузере | **[решено, 2026-10-18]** Отдельный Web Worker со своим рантаймом .NET. С клиентом говорит тем же протоколом, что сервер, через `postMessage`. Клиент всегда реплика. Многопоточный Blazor и COOP/COEP не нужны. |
| Р11 | Подача | **[решено, 2026-10-18]** Всё в `base`, кроме оболочки. Облики видов, звуки, HUD, камера, управление, эффекты, атмосфера, музыка — клиентская часть мода. В клиенте остаются меню, настройки, чат, подключение, сохранения и редактор. |
| Р12 | Данные видов | **[решено, 2026-10-18]** JSON рядом с `.wasm`. Мод — папка: манифест, `data/*.json`, `host.wasm`, `client.wasm`. Данные читает движок без запуска кода. Отсюда патчи модов поверх модов, баланс без пересборки и данные для клиента и каталога. Нынешние `packages/base/data/*.json` переезжают как есть. |
| Р13 | Первая веха | **[решено, 2026-10-18]** Срез на обеих платформах сразу (§6, Н3). Повторяет Rust-пилот К4, но и на десктопе, и в браузере, с хостом в воркере. Так все главные риски проверяются до того, как пишутся механики. |
| Р14 | Система плагинов | **[решено, 2026-10-18]** Код UserPluginSystem копируется в `dotnet/src/Kharos.Plugins` и дальше развивается там, под игру. |

### Решено без обсуждения, технические

- **.NET 11, C# последней версии.** UserPluginSystem уже на `net11.0` (RC1), выпуск — ноябрь 2026.
- **Детерминизм земли.** Клиент строит землю по зерну сам, а клиент и хост могут быть разными платформами (браузер и
  Linux-сервер). Поэтому генератор не вызывает `Math.Sin`/`Math.Pow` платформы, только свою `DetMath`: целочисленный
  хеш (как `Math.imul` в TS), свои приближения на `double` с фиксированным порядком операций. В приветствии хост шлёт
  сумму окна земли; при расхождении клиент просит землю байтами (кадр `LAND` есть и сейчас). Симуляцию считает
  только хост, так что ей кроссплатформенный детерминизм не нужен.
- **Сервер** — ASP.NET Core (Kestrel, WebSocket со сжатием permessage-deflate), NativeAOT, один бинарник под
  linux-x64 и linux-arm64. Let's Encrypt — через Certes, HTTP-01. Kestrel меняет сертификат без перезапуска порта
  (`ServerCertificateSelector`), так что игроков при продлении больше не выкидывает. Ключи `settings.json` те же,
  что сейчас (`apps/server/settings.ts`).
- **WebGPU в браузере — потоком команд.** Вызов JS из C# на каждую команду GPU слишком дорог. Рендер пишет кадр в
  байтовый поток команд (создание ресурсов по номерам, запись буферов, проходы, отрисовка), и один вызов JS за кадр
  исполняет его. Desktop исполняет тот же поток через Silk.NET.WebGPU. Путь кода у рендера один.
- **Шрифты.** Ark Pixel 10/12 и подмножество Unifont запекаются в растровый атлас при сборке (продолжение
  `tools/fonts.py`). Растеризатора шрифтов во время работы нет. IME и вставка в браузере — через скрытый `<input>`.
- **Сжатие** — `deflate-raw` из `System.IO.Compression`, работает и в WASM.
- **Хранилище.** Desktop — файлы в каталоге данных пользователя. Браузер — IndexedDB (сохранения) и localStorage
  (настройки) через interop.
- **Тесты** — xUnit. Сценарные тесты переносятся из `packages/tests`, числа сверяются с TS-эталоном с допуском,
  а не до бита.

## 2. Карта нынешнего кода и его судьба

Две линии игры живут в репозитории одновременно.

**TS — играбельная игра** (около 44 тыс. строк): все механики, сеть, сервер.

```
i18n ─┐  ecs ─┐  base(JSON) ─┐  data ─┐
      │       └──────────────┴───────┴─► sim-ts (15,8 тыс., 39 систем) ◄── shared (земля)
      │                                     │  ▲ клиент берёт ~84 импорта: ~300 правил интерфейса
      │                                  protocol (v52: кодек дельт, сохранение KHRS v23)
      │                                     │
      │                                  host (интерес игроков, бюджет 256 КБ/с) ──► mods (luau.wasm, API v1)
      │                                     │
      └──────────────────────────────────► client (26,5 тыс.: WebGL 2, GUI на Canvas 2D, синтез WebAudio, реплика)
                                            ▲
                         apps/web (Vite)        apps/server (Bun.serve, ACME)
```

**Rust и Luau — целевая архитектура, пилот** (К4 из `docs/content.md`): один юнит, одно здание, производство, приказ
ехать. Ни сети, ни боя, ни стройки, ни браузерной сборки.

```
crates/engine (земля до байта, слои, JS-математика)
   └─► crates/world (столбцы f64, хост, API ctx) ◄── crates/content (mlua, моды, require)
          └─► apps/client (glow, GLSL ES 3, свой UI на fontdue, граф web-audio-api) ◄── mods/base (5 тыс. Luau)
```

## 3. Решение на .NET

```
dotnet/
  Kharos.slnx, Directory.Build.props, Directory.Packages.props, global.json
  src/
    Kharos.Engine/        — без платформы: мир столбцами по схеме модов, порядок систем, буфер команд, события;
                            земля и DetMath; слои; инструменты (пути, поля потоков, ход, столкновения, поиск в
                            радиусе и по лучу, обзор и память, сети-графы, следы, занятость)
    Kharos.Plugins/       — копия UserPluginSystem: абстракции, бэкенд Wasmtime, бэкенд браузера, ABI игры
    Kharos.Content/       — загрузка модов: манифест, порядок по requires, data/*.json, патчи, сумма для сверки
    Kharos.Protocol/      — сообщения, двоичный кодек дельт по схеме, формат сохранения
    Kharos.Host/          — хост: тик, игроки, приказы, интерес и бюджет отправки, чат и команды, пределы
    Kharos.Client/        — реплика, кадр, камера, атлас обликов, UI-ядро, оболочка (меню, настройки, чат,
                            подключение, сохранения, редактор), клиентский API модов
    Kharos.Gpu/           — проходы рендера, WGSL, поток команд; Kharos.Gpu.Silk — исполнение через Silk.NET.WebGPU
    Kharos.Audio/         — API графа; Kharos.Audio.Dsp — DSP на C#; Kharos.Audio.OpenAL — вывод через OpenAL Soft
    Kharos.I18n/          — словари и t(), генератор ключей
    Kharos.Mod.Sdk/       — для мододела: API хоста и клиента на C#, генератор экспортов, сборка NativeAOT-LLVM
  apps/
    Kharos.Desktop/       — Silk.NET Windowing + Input, NativeAOT; хост в том же процессе, в своём потоке
    Kharos.Web/           — Blazor WASM (AOT): canvas, WebGPU и Web Audio через JS, подключение
    Kharos.Web.Worker/    — хост одиночной игры в Web Worker со своим dotnet.js; плагины через JS WebAssembly
    Kharos.Server/        — ASP.NET Core, Kestrel WebSocket, ACME, settings.json
  mods/base/
    mod.json, data/*.json
    Base.Host/            — системы, события, приказы → host.wasm
    Base.Client/          — облики, звуки, HUD, камера, управление, эффекты, атмосфера, музыка → client.wasm
  tests/                  — Kharos.Engine.Tests, Kharos.Base.Tests (сценарии), эталоны кадров и звука
  tools/                  — Balance, Bench, Smoke, FontBake, бенчмарки плагинов
```

Зависимости (стрелка — «зависит от»):

```
Kharos.I18n   Kharos.Plugins   Kharos.Engine ◄─ Kharos.Content
                    ▲                ▲              ▲
                    └──── Kharos.Host ──► Kharos.Protocol
                                ▲             ▲
Kharos.Gpu  Kharos.Audio   Kharos.Client ─────┘   (Client зависит от Engine, Content, Plugins, Protocol, I18n,
    ▲            ▲              ▲                  Gpu, Audio; от Host — нет)
    │            │      ┌───────┼──────────────┬──────────────────┐
Gpu.Silk   Audio.Dsp+OpenAL  Kharos.Desktop  Kharos.Web  Kharos.Web.Worker → Host   Kharos.Server → Host
                                   └──► Host (одиночная игра в процессе)
Kharos.Mod.Sdk — отдельно: от него зависят только моды (Base.Host, Base.Client); ABI описан в нём и в Kharos.Plugins.
```

Правила:

- `Kharos.Engine`, `Content`, `Protocol`, `Host` — без платформы: ни Silk.NET, ни JS interop, ни ASP.NET. Проверяется
  сборкой: у этих проектов нет ссылок на платформенные пакеты.
- Клиент не знает хоста. Одиночная игра — это клиент плюс хост через транспорт: в процессе (desktop) или в воркере
  (браузер).
- Платформа подключается интерфейсами `IGpu`, `IAudioOut`, `IInput`, `IStorage`, `ITransport`.

## 4. Устройство

### 4.1. Граница движка и мода

Граница та же, что в `docs/content.md` §3: движок — мир столбцами, земля и слои, движение (пути, поля потоков,
столкновения), пакетный поиск, обзор, сети-графы, снаряды, сеть и сохранения, клиент. Всё остальное — мод.

Инструменты движка работают пакетами. На вход — список сущностей или точек, на выход — столбец. Что считается над
тысячами сущностей каждый тик, должно быть инструментом, иначе тормозит: теперь каждый тик стоит ещё и копирования через
границу wasm.

### 4.2. ABI мода

Сейчас у UserPluginSystem одна точка входа: `process_buffer(in, inLen, out, outMax)`. Для игры её мало. Экспорты мода
(генерирует `Kharos.Mod.Sdk`):

- `kh_alloc(size)` — память под столбцы и аргументы в линейной памяти мода.
- `kh_load(ptr, len)` — данные мода и схема, раз при создании экземпляра.
- `kh_system(id, n)` — система над `n` сущностями. Движок перед вызовом пишет нужные столбцы в память мода. После
  вызова забирает изменённые столбцы и буфер команд (создание, удаление, компоненты, события, сигналы клиентам).
- `kh_event(id, ptr, len)`, `kh_command(id, player, ptr, len)` — события и приказы игроков.
- Клиентские: `kh_look(kind, canvas)` — облик в атлас при загрузке; `kh_frame(...)` — UI, звук и эффекты за кадр.

Структурированные данные идут через MemoryPack, столбцы — сырыми `f64`/`f32`/`i32` без сериализации. Импорты хоста —
белый список (`HostCapabilityRegistry`): инструменты движка, `random` из зерна мира, журнал. Часов у игровых модов нет
(`host_get_timestamp` убирается): так у модов нет недетерминизма.

Пределы:

- Wasmtime — прерывание по эпохам (уже есть), память — 64–256 МБ на экземпляр: рантайм NativeAOT-LLVM занимает
  мегабайты, нынешние 2 страницы по 64 КБ не подходят.
- Браузер — wasm не прервать снаружи. Хост в воркере замеряет время каждой системы, после трёх перерасходов мод
  выключается. Последнее средство — клиент перезапускает воркер с сохранения. Счётчик шагов вставкой при загрузке
  (`docs/engine.md` §7) — позже, если понадобится.

### 4.3. Бэкенд плагинов в браузере

`Kharos.Plugins` получает второй бэкенд: `WebAssembly.instantiate` в JS воркера. Столбцы копируются так: span C# →
`MemoryView` через `[JSImport]` → `Uint8Array` памяти модуля. Цена копирования на тик — главный риск (§7, Р1) и
меряется первым делом (Н2).

### 4.4. Клиент

- **Рендер.** 11 программ GLSL переписываются в WGSL: земля (`terrain.frag`, 514 строк), осадки (`weather.frag`,
  208), туман, спрайты с палитрой сторон, огни, лучи с тенями, колея, перенос, батч UI. Порядок кадра — как в
  `apps/client/src/render.rs`. Сверка — кадрами против TS-клиента.
- **Облики.** Мод рисует вид на холсте при загрузке: 64 направления × фазы → атлас. Холст — перенос `Pixmap` и
  `atlas.rs`. Сверка до пикселя, как `tools/art`.
- **UI** — немедленный: дерево узлов за кадр, раскладка, девятичастный скин, пиксельные шрифты, подсказки. Перенос
  `gui.rs`/`ui.ts`. HUD и панели видов строит `base`, оболочку — клиент.
- **Звук.** Узлы: осциллятор, шум, сэмпл, biquad, усиление, задержка, waveshaper, панорама, свёртка, константа,
  компрессор, автоматизация параметров (`set`, `ramp`, `exp`, `target`). Шины `battle`, `world`, `interface`, `music`.
- **Ввод.** Мышь, колесо, клавиши, касания. Долгое касание — правый щелчок.

### 4.5. Сеть

Протокол новый, двоичный и по схеме. Компоненты объявляет мод, поэтому кодек строится по схеме, а не по списку
компонентов TS. Из нынешнего остаются квантование (позиции 1/256 тайла, углы 1/10000 рад), варинты, отдельные записи
движения и выстрелов, фильтр по зрителю, бюджет отправки с приоритетом экрана. Слои — изменёнными чанками
(`docs/layers.md`). Код клиентских модов и данные приходят при входе и кэшируются по хешу.

## 6. Порядок работ

Каждый шаг — коммиты, после которых всё рабочее: `dotnet build`, `dotnet test`, TS-игра (`bun test`, сборка)
нетронута.

- [ ] **Н0. Каркас.** `dotnet/` с решением, `Directory.Build.props` (net11.0, Nullable, TreatWarningsAsErrors),
      центральные версии пакетов, `global.json`. Копия UserPluginSystem → `src/Kharos.Plugins`, бенчмарки →
      `tools/`. Задание CI: сборка и тесты .NET рядом с нынешними.
- [ ] **Н1. Ядро движка.** `DetMath`, генератор земли (сверка до байта с TS: эталонные файлы выгружает
      инструмент на Bun), слои, мир столбцами по схеме, буфер команд, события, порядок систем.
- [ ] **Н2. ABI модов и SDK.** `Kharos.Mod.Sdk`, генератор экспортов, сборка NativeAOT-LLVM, мод `hello`.
      Исполнение в Wasmtime и в браузерном воркере. **Замер-ворота:** система над 10 тыс. и 100 тыс. сущностей через
      границу wasm на desktop и в браузере; 39 систем base — бюджет тика 50 мс с запасом. Если не проходит — решение
      о пакетировании систем или о переносе горячего в инструменты движка.
- [ ] **Н3. Срез на обеих платформах (первая веха).** `base`: багги с турелью-стрелком, завод, шесть месторождений,
      производство за кредиты, приказ ехать, расталкивание. Земля, туман, свет, погода, сутки. HUD с мини-картой и
      сеткой 4×3, подсказки, колея, звук моторов, фона, зданий и интерфейса. Desktop (Silk.NET) и браузер (Blazor,
      хост в воркере). Готово, когда обе платформы показывают то же, что Rust-пилот К4, и кадры совпадают.
- [ ] **Н4. Сеть и сервер.** Протокол, кодек по схеме, реплика, интерес и бюджет, сохранение, `Kharos.Server`
      (Kestrel, ACME, settings.json, пределы, пароль, админ). Смоук: сервер, подключение, приказ проходит.
- [ ] **Н5. Механики по разделам** (как К6 в `docs/content.md`). Порядок: стройка, зоны и покрытие → добыча,
      переработка, склады, грузовики, трубы, торговля → энергия и накопители → производство и лимит армии → бой
      (оружие, турели, стены, щиты, боеприпасы, урон по классам) → исследования и уровни зданий → ракеты и
      перехват → тактика, патруль, точки сбора → игроки (союзы, защита новичка, поражение, офлайн-доход,
      месторождения). Для каждого раздела: сценарные тесты из `packages/tests` и числа harness в допуске.
- [ ] **Н6. Подача целиком.** Облики всех видов (сверка кадров), звуки и музыка, все панели HUD, окно исследований,
      редактор, витрина меню, первые шаги, уведомления, сенсорный ввод на телефоне.
- [ ] **Н7. Паритет и переключение.** Смоук всего, баланс в допуске, игровые сессии на сервере и в одиночке.
      Blazor — на gh-pages, сервер из .NET — в релизы. Вайп.
- [ ] **Н8. Уборка.** Удаление `packages/`, `apps/` (кроме .NET), `crates/`, Luau, Cargo и Bun. Документы TS и Rust
      помечаются заменёнными или уходят.

**Нужно:** Н1 — Н0; Н2 — Н0; Н3 — Н1 и Н2; Н4 — Н3; Н5 — Н3 (сценарии на локальном хосте, с Н4 — параллельно);
Н6 — Н3; Н7 — Н4, Н5, Н6; Н8 — Н7.
